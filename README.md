# Интернет-магазин «Web-Larёk»

«Web-Larёk» - это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

В приложении используются две основные сущности, описывающие данные: **товар** и **покупатель**. Для типизации этих сущностей определены соответствующие интерфейсы

### Интерфейс IProduct

Описывает структуру данных товара, который отображается в каталоге и может быть добавлен в корзину

```typescript
interface IProduct {
  id: string; // уникальный идентификатор товара
  description: string; // описание товара
  image: string; // ссылка на изображение товара
  title: string; // название товара
  category: string; // категория товара
  price: number | null; // цена товара (может отсутствовать)
}
```

### Интерфейс IBuyer

Описывает структуру данных покупателя, которые необходимо заполнить при оформлении заказа

```typescript
interface IBuyer {
  payment: TPayment; // способ оплаты
  email: string; // электронная почта
  phone: string; // телефон
  address: string; // адрес доставки
}
```

```typescript
type TPayment = "card" | "cash";
```

## Модели данных

В проекте выделены три модели, разделённые по зонам ответственности:

**ProductCatalog** - каталог товаров
**Cart** - корзина покупок
**Buyer** - данные покупателя

### Класс ProductCatalog

Отвечает за хранение списка всех доступных товаров и управление товаром, выбранным пользователем для просмотра подробной информации

#### Конструктор

Класс не принимает параметров в конструкторе. Инициализация списка товаров происходит через метод `setProducts`

#### Поля класса

- `products: IProduct[]` - массив всех товаров, доступных в каталоге
- `selectedProduct: IProduct | null` - товар, выбранный пользователем для подробного отображения

#### Методы класса

- `setProducts(products: IProduct[]): void` - сохраняет переданный массив товаров в поле products. Вызывается при получении данных с сервера
- `getProducts(): IProduct[]` - возвращает массив всех товаров из каталога
- `getProduct(id: string): IProduct | null` - возвращает один товар по его идентификатору. Используется для получения данных конкретного товара
- `setSelectedProduct(product: IProduct): void` - сохраняет товар, выбранный пользователем для подробного отображения, в поле selectedProduct
- `getSelectedProduct(): IProduct` - возвращает товар, выбранный для подробного отображения

### Класс Cart

Отвечает за хранение товаров, выбранных покупателем для покупки, и предоставляет методы для управления содержимым корзины и подсчёта итоговой стоимости

#### Конструктор

Класс не принимает параметров в конструкторе. Корзина инициализируется пустым массивом

#### Поля класса

- `items: IProduct[]` - массив товаров, добавленных покупателем в корзину

#### Методы класса

- `getItems(): IProduct[]` - возвращает массив товаров, находящихся в корзине
- `addItem(product: IProduct): void` - добавляет переданный товар в массив корзины
- `removeItem(product: IProduct): void` - удаляет переданный товар из массива корзины
- `clearCart(): void` - полностью очищает корзину, удаляя все товары
- `getTotal(): number` - возвращает общую стоимость всех товаров в корзине
- `getCount(): number` - возвращает количество товаров в корзине
- `hasItem(id: string): boolean` - проверяет наличие товара по id в корзине

### Класс Buyer

Отвечает за хранение и проверку данных покупателя, которые он вводит при оформлении заказа

#### Конструктор

Класс не принимает параметров в конструкторе. Все поля инициализируются пустыми значениями.

#### Поля класса

- `payment: TPayment | ''` - выбранный способ оплаты. Пустая строка означает, что способ оплаты не выбран
- `email: string` - электронная почта покупателя
- `phone: string` - телефон покупателя
- `address: string` - адрес доставки

#### Методы класса

Отдельные сеттеры для каждого поля, которые позволяют обновлять данные частично

- `setPayment(payment: TPayment): void` - сохраняет выбранный способ оплаты
- `setEmail(email: string): void` - сохраняет электронную почту
- `setPhone(phone: string): void` - сохраняет телефон
- `setAddress(address: string): void` - сохраняет адрес доставки
- `getOrderData(): IBuyer` - возвращает объект со всеми данными покупателя, собранными из полей класса
- `clearBuyer(): void` - очищает все данные покупателя, возвращая поля в начальное состояние
- `validate(): ValidationError` - проверяет заполненность всех полей. Поле считается валидным, если оно не пустое. Возвращает объект с ошибками: ключ - название поля, значение - текст ошибки. Валидные поля в объект не попадают

Тип `ValidationError` описывает объект с ошибками валидации:

```typescript
type ValidationError = Partial<Record<keyof IBuyer, string>>;
```

Это объект, ключами которого являются названия полей покупателя, а значениями - текст ошибки. Если поле валидно, соответствующий ключ в объекте отсутствует. Пустой объект означает, что все данные заполнены корректно

Пример возвращаемого значения:

```typescript
{
  payment: 'Не выбран вид оплаты',
  email: 'Укажите емэйл',
}
```

В этом примере поля `phone` и `address` заполнены корректно, а в полях `payment` и `email` обнаружены ошибки

## Слой коммуникации

### Класс LarekApi

Отвечает за обмен информацией с сервером «Веб-ларёк». Обеспечивает загрузку перечня товаров и передачу оформленных заказов. Непосредственно HTTP-запросы не формирует - делегирует эту задачу объекту, реализующему интерфейс IApi (например, экземпляру базового класса Api), получая его через механизм композиции

#### Конструктор

`constructor(api: IApi)` - принимает объект для выполнения HTTP-запросов

#### Поля класса

- `api: IApi` - объект, предоставляющий методы `get` и `post` для выполнения сетевых запросов

#### Методы класса

- `getProducts(): Promise<IProductListResponse>` - осуществляет GET-запрос к ресурсу `/product/` и возвращает объект, содержащий массив доступных товаров
- `createOrder(order: IOrderRequest): Promise<IOrderResponse>` - выполняет POST-запрос на эндпоинт `/order/` с данными заказа и возвращает объект, подтверждающий покупку на определённую сумму
